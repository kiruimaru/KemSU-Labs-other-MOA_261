## Что это?

**Conventional Commits** — это стандарт для написания сообщений коммитов, который делает историю изменений понятной и позволяет автоматизировать версионирование и генерацию changelog.

## Базовая структура

```
<тип>(<область>): <описание>

[необязательное тело]

[необязательный футер]
```

### Пример

```
feat(auth): добавить OAuth2 авторизацию через Google

Реализован полный flow OAuth2 с редиректами и обновлением токенов.
Добавлена проверка прав доступа.

Closes #123
```

## Типы коммитов

### Основные типы

- **feat** — новая функциональность для пользователя
  ```
  feat(api): добавить эндпоинт для получения списка пользователей
  ```

- **fix** — исправление бага
  ```
  fix(login): исправить ошибку валидации email
  ```

- **docs** — изменения только в документации
  ```
  docs(readme): обновить инструкцию по установке
  ```

- **style** — форматирование кода (пробелы, запятые, отступы) без изменения логики
  ```
  style: исправить отступы в компоненте Header
  ```

- **refactor** — рефакторинг кода без добавления функций или исправления багов
  ```
  refactor(utils): упростить функцию форматирования дат
  ```

- **perf** — улучшение производительности
  ```
  perf(db): добавить индекс на колонку user_id
  ```

- **test** — добавление или изменение тестов
  ```
  test(auth): добавить тесты для функции login
  ```

- **build** — изменения системы сборки или зависимостей
  ```
  build: обновить webpack до версии 5.0
  ```

- **ci** — изменения CI/CD конфигурации
  ```
  ci: добавить автоматический деплой на staging
  ```

- **chore** — рутинные задачи, не влияющие на код (обновление gitignore, конфигов)
  ```
  chore: обновить .gitignore
  ```

- **revert** — откат предыдущего коммита
  ```
  revert: откатить "feat(api): добавить эндпоинт пользователей"
  ```

## Область (scope)

**Область** — это необязательная часть, указывающая на модуль/компонент проекта, который изменился.

### Примеры областей

```
feat(auth): ...          # модуль авторизации
fix(parser): ...         # парсер
docs(api): ...           # документация API
refactor(db): ...        # база данных
test(components): ...    # компоненты
```

Область можно опустить, если изменение глобальное:
```
feat: добавить поддержку темной темы
```

## Описание

- Пишется в повелительном наклонении: "добавить", а не "добавил" или "добавлен"
- Начинается с маленькой буквы (если не имя собственное)
- Без точки в конце
- Краткое (до 72 символов)

### ✅ Хорошие примеры

```
feat: добавить кнопку экспорта в PDF
fix: исправить утечку памяти в компоненте Table
docs: обновить API документацию
```

### ❌ Плохие примеры

```
feat: Добавил новую фичу.           # не повелительное наклонение, точка
fix: исправления багов              # слишком общее
update: меняю код                   # неправильный тип
```

## Тело коммита (body)

Необязательная часть, которая дает больше контекста:

- Отделяется пустой строкой от заголовка
- Объясняет **что** и **почему**, а не **как**
- Может быть многострочным

```
feat(cache): добавить Redis для кеширования сессий

Старый механизм кеширования в памяти не масштабировался
при увеличении числа пользователей. Redis позволяет:
- Распределить нагрузку между серверами
- Сохранять сессии при перезапуске
- Уменьшить время отклика на 40%
```

## Футер (footer)

Используется для:

### 1. Breaking changes (критические изменения)

Изменения, которые ломают обратную совместимость:

```
feat(api)!: изменить формат ответа эндпоинта /users

BREAKING CHANGE: Поле 'name' теперь разделено на 'firstName' и 'lastName'
```

Восклицательный знак `!` после типа/области — краткий способ указать breaking change.

### 2. Ссылки на issues

```
fix(parser): исправить обработку пустых строк

Closes #234
Refs #123, #456
```

## Зачем это нужно?

### 1. Читаемая история

Быстро понять, что менялось:
```bash
git log --oneline

feat(auth): добавить 2FA
fix(ui): исправить баг с отображением модалки
docs: обновить README
refactor(api): упростить обработчики
```

### 2. Автоматическое версионирование (semver)

- `feat:` → увеличивает **minor** версию (1.1.0 → 1.2.0)
- `fix:` → увеличивает **patch** версию (1.1.0 → 1.1.1)
- `BREAKING CHANGE:` → увеличивает **major** версию (1.1.0 → 2.0.0)

### 3. Автогенерация CHANGELOG

Из коммитов автоматически создается changelog:

```markdown
## [1.2.0] - 2024-10-14

### Features
- **auth**: добавить 2FA (#234)
- **api**: добавить эндпоинт для экспорта данных (#245)

### Bug Fixes
- **ui**: исправить баг с модалкой (#256)
```

### 4. Фильтрация коммитов

Легко найти нужное:
```bash
git log --grep="^feat"          # только новые фичи
git log --grep="^fix(auth)"     # только исправления в auth
```

## Инструменты

### commitizen

Интерактивный помощник для создания коммитов:

```bash
npm install -g commitizen
git cz
```

Задаст вопросы и сформирует правильный коммит.

### commitlint

Проверяет, что коммиты соответствуют стандарту:

```bash
npm install --save-dev @commitlint/cli @commitlint/config-conventional
```

### husky

Автоматическая проверка коммитов перед push:

```bash
npm install --save-dev husky
npx husky add .husky/commit-msg 'npx commitlint --edit $1'
```

## Примеры из реальной жизни

### Новая фича
```
feat(shop): добавить корзину покупок

Пользователи теперь могут:
- Добавлять товары в корзину
- Изменять количество
- Сохранять корзину между сессиями

Closes #89
```

### Исправление бага
```
fix(payment): исправить двойное списание при медленном интернете

При медленном соединении форма отправлялась дважды.
Добавлена блокировка кнопки после первого клика.

Fixes #456
```

### Breaking change
```
feat(api)!: изменить структуру ответа API

BREAKING CHANGE: Все эндпоинты теперь возвращают данные
в поле 'data' вместо корня ответа.

Миграция:
```json
// Было
{ "id": 1, "name": "test" }

// Стало
{ "data": { "id": 1, "name": "test" } }
```

Refs #789
```

### Рефакторинг
```
refactor(auth): вынести логику JWT в отдельный модуль

Улучшает тестируемость и переиспользование кода.
```

## Шпаргалка

```
feat: новая функция
fix: исправление бага
docs: документация
style: форматирование
refactor: рефакторинг
perf: производительность
test: тесты
build: сборка/зависимости
ci: CI/CD
chore: рутина
revert: откат

! после типа = breaking change
(область) = модуль/компонент
```
